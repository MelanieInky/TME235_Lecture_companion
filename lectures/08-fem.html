The finite element method

On the previous page we ended on a slightly frustrating note. The principle of virtual work gives us a beautifully compact problem: find a displacement \(\boldsymbol{u}\), respecting the Dirichlet boundary conditions, such that

\[ R(\boldsymbol{u};\delta \boldsymbol{u}) = \delta W_\text{int} - \delta W_\text{ext} = 0 \tag{1}\]

for every kinematically admissible virtual displacement \(\delta \boldsymbol{u}\). And then we said: we cannot put this on a computer, because there is an infinity of virtual displacements to test with. Time to fix that.

Same bar, now solved for the displacement with finite elements. The trial u(x) is piecewise linear, the sum of ui·φi(x) over hat functions φi. Galerkin's method uses those same hats as test functions: each φj gives one equation. Find the nodal values ui that make every hat test balance.

L2 error of u, your nodal values (RMS over the bar) mm %
L2 error of N, your nodal values (RMS over the bar) kN %

The bar has L = 1 m and EA = 1000 kN, so N [kN] equals du/dx [mm/m]. Node 0 is fixed (u0 = 0), so φ0 is not an admissible test function. Testing with φj gives the Galerkin equation Σi Kji ui = fj, with Kji = ∫ EA φi′ φj′ dx and fj = ∫ q φj dx + P φj(L). The equations are listed with coefficients in kN/mm and right-hand sides in kN; their rows form the global system K u = f. The residual of a test is Wint − Wext for a virtual displacement of amplitude 1 mm, in J.

Each hat test is the equilibrium of one node. In element forces Ne = EA(ue − ue−1)/h, the equation reads Nj − Nj+1 = fj, with the load share fj collected by that node. The last hat gives Nn = fn directly, so you can work back to the wall and then integrate the displacements outward.

Every combination Σ cj φj is also in the space. Its residual is Σ cj × (residual of φj), so once all hats balance, every test in the space balances; press "New coefficients" to try another. The sine is not in the space, so the Galerkin solution does not in general balance it. For a 1D bar with constant EA and consistently integrated loads, the nodal displacements are exact for any n. N, however, is only piecewise constant, equal to the exact N averaged over each element.

Errors are L2 norms divided by √L, i.e. root-mean-square differences over the bar, computed with 5-point Gauss quadrature per element (exact for these polynomials); percentages are relative to the RMS of the exact field. The log–log plot runs the Galerkin solution from n = 1 to 64; the filled markers sit at the current n, the hollow squares show your own nodal values. The slopes in the legend are measured between n = 32 and 64: about 2 for u and 1 for N, i.e. halving h divides the u error by 4 and the N error by 2. For this problem Galerkin gives the smallest possible N error of any nodal values (it is the best approximation in the energy norm) — try beating it. The u error is not minimised the same way: the Galerkin u equals the nodal interpolant here, and other nodal values can give a slightly smaller L2 error in u.

Bonus, not covered in this course: quadratic elements add a midside node to each element, so u is piecewise quadratic and N piecewise linear. Their dashed curves are computed by the same Galerkin procedure (3×3 element stiffness, loads integrated by Gauss quadrature) and converge one order faster: slope about 3 for u and 2 for N. Under a uniform load the exact u is itself quadratic, so it lies in the quadratic space and the error is zero for every n — there is then nothing to plot. The hand-solving part above uses linear elements only.

Hat tests count as balanced below 0.015 J, which covers typing nodal values to three decimals. The combination's threshold scales with Σ|cj|. Parts of N outside the plotted range are not drawn.

WarningEvery test balances. Have I found the exact solution?

You already know the answer from the previous page: no. You have only shown that your \(u\) passes every test in your space. The widget makes the point with the sine row, which is a perfectly admissible virtual displacement that is not a combination of hats, and which does not balance.

What is true, and is the reason any of this works, is that the residual of such an outside test shrinks as you refine the mesh, and that the solution converges. The log–log plot at the bottom measures it: halving the element size divides the error in \(u\) by about 4 and the error in \(N\) by about 2. Second order for the displacement, first order for the force — the force is one derivative worse off, which is a pattern you will meet again.

A warning about a coincidence: for this bar, the Galerkin nodal displacements come out exactly right, for any number of elements. Do not read too much into it. It is a 1D bar with constant \(EA\) and consistently integrated loads, and the property does not survive in general. The error is still there, it just lives strictly between the nodes.

It is a linear system

Look again at ?@eq-node-equilibrium. The left-hand side is linear in the nodal displacements, because \(N\) is linear in \(u\) and \(u\) is a linear combination of the \(u_i\). So each test gives one linear equation, and testing with \(\varphi_j\) for every \(j\) gives

\[ \sum_i K_{ji} u_i = f_j, \qquad K_{ji} = \int_0^L EA \frac{\mathrm{d}\varphi_i}{\mathrm{d}x}\frac{\mathrm{d}\varphi_j}{\mathrm{d}x} \, \mathrm{d}x, \tag{2}\]

or in matrix form \(\boldsymbol{K}\boldsymbol{u} = \boldsymbol{f}\), with \(\boldsymbol{K}\) the stiffness matrix and \(\boldsymbol{f}\) the load vector. Three things about it:

  1. It is symmetric. The expression for \(K_{ji}\) does not care which of the two functions is the trial and which is the test. That is a gift from the Galerkin choice, together with the symmetry of the elastic constitutive law.
  2. It is sparse. \(K_{ji} = 0\) unless the hats \(i\) and \(j\) overlap, so here the matrix is tridiagonal. In 3D it is not tridiagonal, but it stays sparse for the same reason.
  3. Without the support, it is singular. Every row of \(\boldsymbol{K}\) sums to zero, because translating all the nodes by the same amount stretches nothing and stores no energy. The bar would be floating in space. Prescribing \(u_0 = 0\) is what removes that rigid-body motion.

A program does not assemble Equation 2 by evaluating global integrals. It notices that each element contributes to exactly two nodes, computes the same small element stiffness matrix

\[ \boldsymbol{k}_e = \frac{EA}{h}\begin{pmatrix} 1 & -1 \\ -1 & 1 \end{pmatrix} \]

for every element, and adds it into the rows and columns of that element’s two nodes. This is assembly, and it is the step that makes the method practical: all the physics is in a small matrix computed element by element, and the global problem is bookkeeping.

Equation 1 residual (hat test φ₁): 4u₁ − 2u₂ − f₁ J
Equation 2 residual (hat test φ₂): −2u₁ + 2u₂ − f₂ J

The bar has L = 1 m, EA = 1000 kN and two elements of length h = 0.5 m, so each element stiffness is EA/h = 2 kN/mm. Loads are integrated consistently, fj = ∫ q φj dx, plus P at the tip. Each row of K u = f is one hat test: row j says the virtual work of φj balances. In the plane, row j is a line, and a trial point lies on it exactly when that test balances; the solution is where the lines cross.

Assembled without the support, K is singular: moving every node by the same amount stretches nothing, so K·(1, 1, 1) = 0. The support u₀ = 0 removes that rigid-body motion. Its row and column are struck out; the struck row is not lost, it gives the unknown reaction R once u is known.

Forward elimination replaces equation 2 by equation 2 + ½·equation 1. That is a different line through the same intersection, one that no longer involves u₁, so u₂ can be read off directly; back-substitution then gives u₁. For n elements K is tridiagonal and the same two sweeps solve it in a number of operations proportional to n. This direct solve is what FE codes do for linear problems; iterative solvers and Newton's method for nonlinear problems are beyond this course. The same intersection is also where the potential energy ½uᵀKu − fᵀu is smallest.

Nodal values move in steps of 0.001 mm; a residual counts as zero below 0.015 J. Drag the point or tap the plane to move it.

Two things to look out for while stepping through. First, elimination replaces one equation by a combination of the two, which moves a line but not the intersection: the solution is untouched, which is the whole justification for doing it. Second, the row of the fixed node was struck out, not thrown away. It still holds, and once \(\boldsymbol{u}\) is known it hands you the support reaction for free.

What changes for a real problem?

Not as much as you would think. The recipe is always the same three choices:

  1. A mesh of the domain, into elements.
  2. A space on that mesh: shape functions attached to nodes, typically piecewise polynomials, one set of unknowns per node.
  3. Galerkin tests: the same shape functions, minus the ones that are not kinematically admissible.

In 2D or 3D, the elements are triangles, quadrilaterals, tetrahedra…, and \(\boldsymbol{u}\) is a vector, so each node carries two or three unknowns instead of one. The internal virtual work \(\int_\Omega \sigma_{ij}\delta\varepsilon_{ij} \, \mathrm{d}\Omega\) is most conveniently written in the Voigt notation of the first page, and the element stiffness matrix becomes an integral of \(\boldsymbol{B}^\mathsf{T}\underline{\underline{C}}\,\boldsymbol{B}\), where \(\boldsymbol{B}\) is whatever turns nodal displacements into strains. It is a bigger expression than \(\frac{EA}{h}\left(\begin{smallmatrix} 1 & -1 \\ -1 & 1\end{smallmatrix}\right)\), and it is computed numerically rather than by hand, but it enters the assembly in exactly the same way. Everything after that — assemble, apply the Dirichlet conditions, solve, recover the reactions — is identical to what you just did with two elements.

What we have skipped: how those element integrals are evaluated in practice (numerical quadrature), higher-order elements, what happens when the material is not linear elastic and \(\boldsymbol{K}\) starts depending on \(\boldsymbol{u}\), and the whole question of how you solve a sparse system with millions of unknowns without doing elimination by hand. All of that is another course. But the part that makes it mechanics rather than linear algebra, you now have: it is the principle of virtual work, tested against a finite number of well-chosen virtual displacements.
